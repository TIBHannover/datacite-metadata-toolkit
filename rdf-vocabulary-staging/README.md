# rdf-vocabulary-staging

This directory holds the **source files of the DataCite linked-data vocabulary**. These are the files you edit when you add or change a vocabulary term, class, property or context mapping. The build scripts in `../rdf-build-scripts/` read this directory to produce the distribution files and the publication bundle in `../production-namespace/`.

Despite the folder name, every file uses the canonical namespace `https://w3id.org/tib/datacite/`. The name is historical.

```
├── context/
│   ├── fullcontext.jsonld          # current JSON-LD context (same as the 4.7-r2 file)
│   ├── fullcontext-4.7-r2.jsonld   # frozen context for 4.7-r2
│   └── fullcontext-4.7.jsonld      # frozen context for 4.7
├── manifest/
│   ├── datacite-current.json       # names the current version (4.7-r2)
│   ├── datacite-4.7-r2.json        # inventory for 4.7-r2
│   ├── datacite-4.7.json           # inventory for 4.7
│   ├── datacite-4.6.json           # inventory for 4.6
│   └── release-matrix-4.6-4.7.json # what changed from 4.6 to 4.7
└── dist/        # whole-vocabulary downloads (JSON-LD, Turtle, RDF/XML, OWL), one set per version
```

`dist/` and the `*/index.html` pages are generated by `build-distribution.js`, `generate-owl-file.py` and `generate-index-pages.js`, and are committed so that the publication bundle can be reviewed. Do not edit them by hand.

## File types

### `class/`

Each file defines one DataCite entity as an RDF class: `@id` (its permanent IRI), `@type` `rdfs:Class`, `rdfs:label` and `rdfs:comment`.

Example: `class/Resource.jsonld` defines the resource that a DataCite record describes.

### `property/`

Each file defines one DataCite metadata field as an RDF property: `@id`, `@type` `rdf:Property`, `rdfs:label` and `rdfs:comment`. The fourteen properties whose values are nodes in 4.7-r2 (`title`, `creator`, `description`, ...) also have an `rdfs:range` naming their class and a `skos:scopeNote` saying where the text goes.

Whether each property holds text or a node is listed in `../rdf-build-scripts/property-value-kinds.json`; the OWL files use that list.

### `vocab/`

Each subdirectory is one SKOS concept scheme:

- **`<scheme>.jsonld`**: the scheme, listing its terms with `skos:hasTopConcept`
- **`<Term>.jsonld`**: one file per term, with `skos:prefLabel`, `skos:notation` (the value as written in DataCite XML and JSON), `skos:definition`, `skos:inScheme`, and sometimes `skos:closeMatch` or `skos:exactMatch` links to external vocabularies
- **`context.jsonld`**: the JSON-LD context the term files use

The JSON Schema and the SHACL shapes take their lists of allowed values from these folders (`../rdf-build-scripts/build-json-schema.py` and `build-shapes.py`), so a new term file is enough to allow a new value everywhere.

### `context/fullcontext.jsonld`

Maps the keys of DataCite REST API JSON to IRIs, so DataCite JSON can be read as linked data:

```json
{
  "@context": "https://w3id.org/tib/datacite/context/fullcontext.jsonld",
  "@id": "https://doi.org/10.1234/example",
  "titles": [{ "title": "Example title", "titleType": "Subtitle" }]
}
```

Each title becomes its own node, with the text in `rdf:value` beside its `titleType`. For complete RDF (node types, language tags, creator order), use `../validation-and-conversion/scripts/datacite_to_rdf.py`.

Changing the current context needs a new revision with its own frozen copy; a test fails if `fullcontext.jsonld` and the frozen file of the current version differ.
